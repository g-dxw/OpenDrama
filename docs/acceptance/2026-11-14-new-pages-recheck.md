## 支付复核修正

- 外部退款进入人工复核后，后续回调或重试不能绕过复核自动结算；自动结算要求完整冻结来源、匹配退款标识/金额/币种。
- 已取消的旧订阅保留历史权益、价格和支付账号；新的已付订阅可以建立新绑定，旧迟到事件不能抢占新绑定。
- 商品改价原因进入版本关联审计。订单和退款详情展示实际来源与是否满足未消费自动退款条件。
- 同一用户的订阅 Checkout 在钱包锁内持久占位；已完成或已付但首张发票未处理时仍阻止重复订阅。只有 Stripe 确认过期才释放，过期检查与替换占位期间不释放锁。
- 新增独立订阅生命周期事实和冻结的 Checkout 请求上下文。首张发票前取消、重复和乱序事件不丢失；同秒取消/恢复在新购前从旧账号查询实际状态，模糊或失败时不创建新订阅。
- Stripe 凭据轮换须验证同一商户和模式；不同商户另建账号。旧签名秘密加密保留短期过渡，接口不返回明文。
- 新商业接口全部受 billing API key scope 约束。PC 提供继续原付款、确认取消后改购、同 key 重试和人工处理入口；取消会员占位不清除无关金币订单的幂等 key。

## PC 账户切换与异步状态

- 旧账户或游客请求的 401 不能清除之后的新登录；仅当前实际携带的令牌失效时触发退出。
- 客服列表、详情、草稿和迟到响应随身份隔离；404 或列表失败不能显示上一个账户的会话。
- 播放信息、互动和解锁结果绑定请求身份；旧视频卸载时不能用新账户令牌上报旧进度。
- 推荐流登录恢复的点赞不会被迟到首屏覆盖，数量仅按真实差分更新；身份切换重置分页，首屏失败重试不能携带旧账户游标。
- 评论的本人待审正文和草稿按身份隔离，迟到响应不会回显。游客评论登录后保留原操作，只提交一次；评论弹层支持焦点限制、Escape 和焦点恢复。
