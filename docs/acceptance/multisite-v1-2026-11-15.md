# MiniTV 多站点 V1 本地验收记录

日期：2026-11-15（上海时区）。开发分支：`codex/open-source-multisite-v1`。

## 已实现

- 已验证域名决定公开站点；未知主机拒绝访问，后台身份不能通过请求头切换站点。
- 各站独立员工、观众、第三方身份、验证码、会话、钱包、权益、订单、观看记录和经营统计。
- 独立或显式复用 Stripe 商户；按存储订单及商户签名处理回调、重试、退款和续费。历史 live 商户不受未验证占位模式误判影响；不同名称下的同一商户仍需显式确认复用。
- Web/H5 共用构建产物，运行时加载品牌、语言、币种、时区和功能开关。
- 品牌草稿、短时授权预览、发布、回退；角色撤销后预览失效。
- 公司母版、审核版本、视频资源和分发授权；导入独立草稿、幂等重试、显式采用新版。
- 中央字幕随版本冻结，跨站复用 URL；导入、详情和播放按授权语言过滤，旧版及本站修改保留。
- 购买及播放前披露内容截止时间；新扣币记录当时的授权期限和版本，重复请求不重复扣币或审计。
- 通用 Docker 包、首次管理员初始化、部署说明、数据库备份和隔离恢复脚本。

## 全新容器安装

使用独立项目 `minitv-verification-final`、空 PostgreSQL 16 数据卷和独立 Redis 7 数据卷完成初始化。API、数据库及缓存健康检查通过；迁移服务正常退出，Nginx 提供三端静态文件和同源 API。

`scripts/verify_selfhost.py` 经真实反向代理完成 12 组行为验证：健康状态、新公司不显示未使用兼容站点、创建两个站点、语言/币种/时区、默认套餐币种、未知域名拒绝、品牌草稿隔离、预览及跨站拒绝、发布回退、静态页面和 CLI、管理 API 路由、开发支付回调关闭。

容器实测修复了健康检查对 SQLAlchemy 驱动 URL 的兼容，并为失败状态提供不含连接信息的 503 响应。临时验证数据库凭据已轮换。

本机旧 WSL 内核的默认 Docker 网络及内存条件不稳定。验收使用独立 Docker 20 引擎、VFS、主机构建网络和临时 4GB WSL 内存上限；这些兼容设置不写入通用 Compose 配置。测试环境覆盖中明确启用 Bunny fake、禁用邮件发送及真实商业化调用。验收结束后已停止专用容器、数据库与 Redis，恢复 iptables 默认选项，并移除本次创建的临时 WSL 内存配置；私有测试配置保存在忽略目录中。

## 迁移与备份恢复

[独立升级演练记录](multisite-upgrade-probe-2026-11-15.md) 验证旧版本 76 张业务表的数据、原 ID、余额和权益；最终版本 87 张业务表备份恢复一致，旧内容仍保持本站私有。

容器内另外执行交付的 `backup.sh` 和 `restore.sh`，恢复到新数据库而不覆盖源库。87 张业务表和 Alembic 版本表共 **88** 张表，逐表计数及完整行内容摘要完全一致。

原 JJTV 反向代理新增同源 API 路由后，使用实际 Nginx 二进制进行语法检查通过；未访问或修改现有生产服务器。

真实浏览器连接独立 API，验证公司内容上传、转码状态、质检、授权、本站导入、独立新版草稿、品牌预览/发布/回退、两个站点隔离、390px H5、功能关闭、未知主机拒绝和纽约时区截止展示。
