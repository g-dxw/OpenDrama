# India 角色委托授权

任务：[india-short-drama #104](https://github.com/88jj-com/india-short-drama/issues/104)。

## 员工使用方式

启用后，员工登录 JJTV 的 India 租户即可进入内容运营。租户管理员在这里维护员工和角色，分别勾选查看、编辑、上传、定价、审核、上下架权限。页面按有效权限显示操作，India 接口再次执行相应权限和业务校验；员工无需再连接旧站账号。

平台人员仍需显式进入 India 支持会话，操作归因于真实平台账号。租户管理员只管理已开通的 India 租户能力，角色名称不会授予旧站全局权限。消费者、会员、钱包、订单和财务不在该通道内。

## 双端配置

新模式默认关闭。JJTV 设置 `INDIA_JJTV_DELEGATED_ENABLED=true`，`INDIA_JJTV_DELEGATED_SECRET_FILE` 指向受保护的独立密钥文件。服务器现有只读 `/run/secrets/india-client` 挂载可以承载该文件，例如 `/run/secrets/india-client/delegated.key`。配置只放在受控运行环境，不提交密钥、真实环境文件或浏览器令牌。

India API 必须先部署匹配的受信委托 provider，使用配对的独立密钥和启用配置。不能只发布前端或只开启 JJTV 开关。此密钥不得复用旧站账号密码、MFA 种子、支付密钥、`TENANT_CONNECTION_KEY` 或专用密码 provider 的客户端密钥。JJTV 只允许固定 India 来源和已有内容路由，不提供通用代理。

委托开关开启但缺少有效配置时，页面显示服务配置错误，接口拒绝操作。不会自动改用共享旧站员工身份。关闭开关时仍可使用原专用密码连接模式；旧站直接登录的认证规则保持兼容。

## 权限、签名和审计

每次请求以当前服务端有效权限为准，交互式会话、租户状态、功能开通和角色均重新检查。证明携带租户、真实账号 ID、账号类型和细粒度权限，绑定请求方法、路径及原始查询、正文摘要、内容类型、长度和幂等键。签名只由后端生成，浏览器不能提交可信角色声明。

证明有效期为 30 秒，并由 India 在共享数据库中原子消费一次性 nonce；篡改、过期、重放、错误租户或权限不足均拒绝。上传正文继续流式传输，授权绑定上传资源、内容类型、长度和幂等键，内容仍由原接收器的预留、归属、大小和校验规则验证，不把大文件完整缓存到内存。

停用账号、收回角色、暂停租户或关闭功能后，后续请求不再签发授权。已签发证明最多存在 30 秒窗口，India 已接受的业务操作不会被宣称自动回滚。两端保留真实操作人、资源、结果和来源请求编号；不会在审计中保存密钥或完整证明。

## 验证与交付

两端必须共同验证权限组合、字段级定价限制、跨租户拒绝、签名篡改和过期、防重放、流式上传、真实操作人审计，以及旧站认证兼容。页面验证覆盖直接进入、无权限操作、加载和配置失败；本地隔离测试不冒充生产验收。

本次不执行生产发布。JJTV 发布仍走 `scripts/release.py`；India 仍需按其现行源码、审查、CI 和发行规则准入。组织 India 仓库当前缺少 `main` 的事实不能由本次功能分支或此前的单次例外替代。
