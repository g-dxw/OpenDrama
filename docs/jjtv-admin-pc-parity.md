# JJTV 管理端与完整 PC 观众端

本分支以 MiniTV 公开产品界面为参考，使用 JJTV 自营数据与品牌。没有复制参考站数据、账号、商户配置或密钥，也没有部署生产。

## 业务能力

- 管理端：内容付费形态筛选、会员观看规则、非会员试看、单集覆盖价格、多语言字幕、频道中英文名称编辑；邮箱验证码、Google 和 Facebook 动态配置。
- 商业化：Stripe 账号和价格绑定、版本化套餐与金币包、每个付费周期的基础和赠送金币、金币来源和消耗、订单与未消费订单全额退款。
- PC：推荐、分组片库、搜索筛选、推荐流、选集、签名播放、字幕、历史续播、收藏、会员和金币购买、订单确认、个人资料、奖励及工单。
- 客服：工作台、队列、批量操作、分派、公开回复与内部备注、合并、工作日历和 SLA、服务质量与评分。
- 归因：Meta/TikTok 像素、来源、站内计划链接、注册及支付事实、持久化回传和失败重试；不创建外部广告或修改预算。

## 兼容和权限

新商业、登录配置、客服和归因模块只绑定 JJTV 自营。其他原生租户和 India 连接器不自动获得这些能力。内容字幕继承原生内容归属，逐语言上传、删除、默认轨和单集价格操作分别校验上传或定价权限。

既有自定义角色不自动扩权。租户管理员可在角色管理中分配新增权限；退款需要独立 finance.refund，金币导出需要 coins.export，客服设置和报表也有独立权限。前端菜单隐藏不代替服务端授权。

PC 已赞页面继续保留 #account/likes 等界面链接，传输使用既有 /v1/me/lists/like。推荐流的游客免费标记不替代用户资格；已登录会员或金币解锁条目重新请求服务端播放授权，拒绝响应不会挂载媒体或暴露流地址。

PC 与 H5 分别保存会话，同账户共享服务端权益，不提供跨子域 SSO。保留 #preview 和 #watch/<id>；旧会员 checkout 接口仍可使用，但新订单走统一产品快照和权益来源。

统计和任务业务日沿用 America/Los_Angeles，不改为参考站的北京时间。

## 桌面、移动与语言

参考站实测以 1024px 区分两套界面：1024px 起为 PC，低于该宽度加载独立 H5 组件及底部导航。PC 不再靠手机媒体规则缩成单列；只有 PC 支持的金币商城、客服等深链接保留 1024px 桌面画布，并显示移动首页入口。旧剧集、选集、搜索及账户链接映射到对应 H5 页面，不静默回到首页。

H5 遇到明确的 checkout_expired/new_purchase 时显示“重新发起支付”，仅在当前账户与原缓存意图仍匹配、用户再次点击后创建新幂等键。绕过支付返回地址时，旧订单通过仅本人可查的 GET /v1/commerce/orders/{order_no} 核对最小产品信息与真实结算记录；只有已支付或已全额退款的订单，在结算确认后才显示显式“开始新的购买”。账户、产品和原缓存意图必须仍匹配才可换键；网络未知、未结算、取消或任意回跳参数不会自动清缓存、换键或下新单。

H5 播放权限响应绑定当前登录会话与剧集；登录后重新查询服务端准入，再恢复原选集或解锁操作。身份变化会立即隐藏旧权限，并清理旧媒体、字幕及上报；迟到的旧权限或视频地址不能覆盖当前身份。

同源加载仍使用独立的 PC/H5 登录存储。已开启的支付、待处理订单恢复和支付回跳保留发起端，改变窗口宽度不会丢失交易操作或复制 token。两套样式随页面挂载卸载，避免全局 CSS 互相覆盖。

PC 支持 English、Deutsch、Français、Español、Português、Italiano、日本語、Русский、简体中文。语言菜单支持键盘，选择后跨页及刷新保留；日期、金额和金币按所选地区格式展示，币种不转换。剧名、客服正文和运营配置文案保持原始数据，不作为界面翻译冒充。H5 保留现有中英文界面。

会员页采用推荐角标、独立价格行、赠币栏、权益列表及底部对齐按钮；管理端采用版本化套餐卡片，停用状态、推荐、金币构成及上下架权限清晰可见。真实年付订阅可展示月均价格与相对同币月付的节省，始终同时展示全年实扣；周付、一次性及未知周期不自动折算。赠币按实际支付周期展示，不声称每月发放。

## 订单与退款

订单在调用 Stripe 前固定产品版本、价格、币种、权益和支付账号。一次性购买按 PaymentIntent、订阅续期按 Invoice 结算。重复事件不重复入账；乱序的失败事件不撤回已支付权益。旧订阅、回调和退款继续使用其原支付账号，停用账号只阻止新购买。

环境账号 env 的新旧 Webhook 地址共用原兼容分派器：先处理受管订单，再兼容历史订阅续期与取消；其他支付账号不进入历史账号分派。回调重复投递不重复结算，取消订阅不撤回一次性通行证。

用户取消续费与管理员到期取消共享持久取消意图，网络结果未知时继续原幂等键。成功响应后仍查询原支付账号下的订阅当前状态；若此前取消已被恢复取代，返回明确重试提示，后续确认使用新意图，不把 Stripe 缓存响应当作当前取消成功。乱序回调和旧取消周期的事件不能回退最新生命周期或清除新的取消意图。

管理员立即收回会员时，同事务审计冻结当时已知的原支付账号/订阅绑定及具体会员权益来源，包含退款冻结中的一次性权益，覆盖已取消的历史绑定；到期取消不产生这类撤销记录。旧绑定的迟到付款仍记录已付、结算、金币及归因，但不重新授予会员，也不会覆盖后来新增的手工通行证或新订阅。退款失败仍按原来源释放金币；被行政撤销的旧会员权益保持撤销。

会员是否已使用，以真实播放准入为准：只要会员是签发流地址的必要条件，即使该集已用金币解锁，也在签流前记录会员来源消费；公开已解锁内容、免费试看和旧权益覆盖的未来购买不会误记。供应商首单佣金排除续费，使用固定的签名发票初购/续费事实处理乱序回调，旧数据兼容原内部订单标志；原单退款不会让续费变成首单。

每个金币来源有剩余量和消费分摊，按先进先出分配。退款只针对可证明未消费且可完整撤回的本订单来源，发起时锁定钱包并冻结待退金币与会员权益。网络结果未知时保留冻结，只查询并核对原退款，不在幂等键保留期之外重新创建退款；确认失败且具备原始退款身份和金额证据才释放冻结。

会员调整审计在钱包锁内按实际变更时点记录，退款资格与执行使用同一事实，避免事务先开始但后完成的调整漏判。

已消费、部分退款、历史来源不明、人工修改过的会员权益和供应商后台发起的退款进入人工核对，不通过清空全部会员或扣成负余额处理。套餐基础和赠送金币按实际支付周期发放；年付套餐不会凭空按月重复发币。

## 配置与迁移

追加迁移链为 a1114content → a1114commerce → a1114support → a1114permissions → a1114lifecycle → a1114cancel_intent。旧定价默认保持会员可观看、原免费集数和原单字幕；现有账号、订单和钱包不重置。

数据库降级先锁定相关表并检查数据。已有商业权益、结算、退款、订单来源金币、消费分摊、受管订阅，或仍绑定外部支付意图的未付订单时，拒绝删除旧结构无法无损表示的数据；有取消操作记录时也拒绝删除取消意图字段。离线 SQL 不能绕过这些检查。保留原库并先核对交易、采用向前修复；不要手工删除记录来绕过拒绝。纯旧订单、历史余额和无外部支付意图的弃单保留兼容回退检查。

保存供应商密钥前，服务端必须配置有效的 Fernet SETTINGS_ENCRYPTION_KEY。密钥不可提交到源码。数据库中的凭据加密存储；查询只返回配置状态与掩码。空密钥保留原值，明确的 clear_* 才删除，删除后不会意外回退到环境中的旧密钥。

Stripe 原环境账号作为 env 账号继续可用。新账号应先用测试模式验证账号、价格、回调签名、续费和退款；PC 支付回跳只接受允许的 JJTV 站点。OAuth 供应商需要分别配置 PC/H5 允许来源。

落地访问按 JJTV、投放计划与精确设备标识关联注册，缺失或不匹配时不从公共计划号推测其他访客的点击。首次注册归因上下文固定，后续同计划支付继承点击上下文；不同计划不携带旧点击。

归因像素默认测试模式，需填写供应商测试事件码后才能启用。启用后台投递使用 ATTRIBUTION_WORKER=1，或运行 python -m app.modules.attribution.worker --once。事实记录只入队，供应商确认接收后才标记送达。测试事件不计入业务转化统计。

## 验证入口

- 后端：backend 目录运行 python -m pytest -q，必须使用可销毁的独立 PostgreSQL/Redis。测试夹具会创建测试库和清理专用 Redis DB。
- 三端构建：分别 npm ci，然后从干净提交运行 python scripts/build_frontends.py --frontend web、h5 或 admin。
- PC：npm run accept:consumer、accept:subtitles、accept:visual、accept:locales 和 accept:surface；游客不能请求锁集流，登录后恢复操作，支付返回核对具体订单，字幕包含旧 SRT 转换。
- H5：npm run verify:consumer，保留原认证、个人中心和奖励流程。verify:home 是另外的真实内容浏览检查，不用模拟数据声称通过。
- 管理端：npm run accept:parity，检查新增页面、1280/1440/1920 布局、只读角色、直接路由、内部备注和跨页签配置保存。

浏览器验收使用明确标记的测试夹具；后端测试使用真实迁移和数据库，Stripe/邮件/广告供应商通过受控替身隔离。它们不能代替实际供应商测试环境联调，也不代表生产验收。

CI 包含后端、迁移、发布版本分配、三端构建以及三端浏览器验收。后续生产发布仍必须遵循仓库已有 scripts/release.py 发布入口和共享锁流程。
